<h1>不停问 · dont-stop-ask</h1>

**一个从不替你回答问题的研究工具。**

把你真正好奇的事情交给它——比如「美国对中国的关税会影响世界其他地方吗？」——它会返回一张更好的问题地图：
每个问题都挂着真实且经过核实的阅读材料，每个问题都附带一个在你开始阅读**之前**要做的核查动作。你在地图上
探索，遇到真正有意思的问题时，把它再展开成九个。

它不总结材料，不代写文章，也不告诉你该站哪一边。这是设计，不是缺陷。

## 为什么做这个

大多数人认真做研究时的流程是：搜索、略读、改写、加引注。而真正让人学到东西的流程是：把问题磨锋利、找出谁
在反对、弄清每项研究究竟**测量**了什么，然后给出一个能当面为之辩护的立场。

会总结材料的 AI 只是让第一种更快。这个工具试图让第二种成为可能——办法是把常见的助手模式反过来。研究助手
替你默默核查来源，因为你本来就会核查；而在这里，**核查本身就是重点**，所以凡是工具能替你做的判断，都被交
还给你，变成一个你要亲自执行的动作。

两项研究结论决定了整个设计：

- 专业事实核查员判断一个陌生来源只需约 90 秒，方法是**离开当前页面**，去看独立来源怎么说。学生*以及大学
  教授*却习惯在页面内往下读，追逐那些轻易就能伪造的线索，花五倍的时间，却更常出错
  （Wineburg & McGrew, 2017, 2019）。**教授同样失败，正是这个工具不只面向新手的原因**——熟悉一个领域，
  并不等于会评判该领域里的来源。
- 自己生成解释的效果远胜于反复重读，但前提是已有足够背景知识去生成解释（Pressley et al., 1992;
  Woloshyn et al., 1994）。所以问题的顺序很重要，过早出现的难题只会换来沉默。

## 适合谁用

任何有一个值得认真调查的问题的人。写论文的人。工作中要做决定、想看到真实证据的人。读了一篇文章、想知道它
是否可信的人。读书小组。记者。周日突然好奇起来的人。

它有两种运行方式：

- **solo（独立）** —— 你在研究自己的问题。简报写给你自己的「稍后的你」，并会警告哪些章节提前读会破坏探究。
- **guided（有人陪）** —— 有人在支持这项研究：老师、导师、主管、学习伙伴或家长。简报写给他们，并假定他们
  对这个主题一无所知。

难度和阅读水平是根据你自述的已有知识来校准的，而不是根据假定的年龄或学历。

**用任何语言提问都可以。** 用中文提问，返回的就是中文的问题集——卡片、简报、复述问题都是中文，查看器的
界面也会跟着切换。阅读材料保持在该题目最强文献所用的语言里（往往是英文）；当材料语言和你的语言不一致时，
卡片会明说，并把「读英文文献」当作一项被点名的难度来对待，而不是装作它不存在。

## 五条铁律

每一套问题都在这些规则下生成，它们高于其他一切指令：

| | 规则 | 原因 |
|---|---|---|
| 1 | **绝不编造来源** | 真实作者 + 真实期刊 + 看似合理的年份，是最危险的幻觉：搜一下作者名字，看起来就像核实过了 |
| 2 | **绝不回答它自己提出的问题** | 如果这套问题让你不打开任何材料就能完成工作，那它已经失败了 |
| 3 | **给动作，不给结论** | 不说「这家智库拿了行业资助」，而说「搜它的名字加 *funding*，然后你自己判断」 |
| 4 | **不用引导性问题** | 两个同样审慎的人，必须能得出不同却都站得住的答案 |
| 5 | **不做伪装的记忆题** | 「关税是什么？」是检索；「为什么明知抬高本国物价还要征关税？」才是探究 |

当某个来源无法核实时，它会**标注为 unconfirmed** 出场，并明确写出到底哪一部分没能确认。范例里就有一个。
这是正确的结果，不是缺陷——而且简报会告诉你：抽查就从这里开始。

## 运作方式

```
  你粗糙的问题
        │
        ▼
  /dont-stop-research  ──── 在 Claude Code 中运行，需联网搜索
        │                     · 磨锋利问题（并展示推导过程）
        │                     · 生成最多 9 个问题，覆盖 7 种问题类型
        │                     · 每个问题配 1–3 份分级阅读材料，逐一搜索核实
        │                     · 按相关度分组，按你的背景评定难度
        ▼
  三个文件 ────────────┬─── question-set.md    完整记录，含预判答案
                       ├─── question-set.json  无剧透的工作面（由 schema 强制）
                       └─── research-briefing.md   文字版导读
                                │
                                ▼
                          viewer/  ── 把 JSON 渲染成力导向图
                                      点圆点 → 阅读材料 + 怎么读
                                      点展开 → 把该问题长成另外 9 个
```

**Claude Code 是引擎，这个仓库是技能和地图。** 核实来源需要联网搜索，所以生成发生在 Claude Code 会话里，
而不是浏览器里。查看器是纯静态的——不需要服务器，不需要 API key，没有任何东西要部署。

## 安装

需要 [Claude Code](https://claude.com/claude-code)；如果想用校验脚本或本地预览，还需要 Python 3。

```bash
git clone https://github.com/cadillacyz/dont-stop-ask.git
```

然后把技能装进 Claude Code：

```bash
cp -r dont-stop-ask/skills/dont-stop-research ~/.claude/skills/
```

Windows PowerShell：

```powershell
Copy-Item -Recurse dont-stop-ask\skills\dont-stop-research $HOME\.claude\skills\
```

## 使用

启动一次陪伴服务器，然后让它一直开着：

```bash
python scripts/serve.py
```

打开 <http://127.0.0.1:8000/viewer/>。你会看到一个问号和一个输入框。写下你想知道的事，再补一句你已经
知道什么，然后按 **Ask**。

接下来会发生什么，取决于一件事——`claude` 命令行工具是否在你的 PATH 里：

| | 装了命令行工具 | 只装了桌面应用 |
|---|---|---|
| **Ask** | 就地运行技能，实时显示进度，完成后图谱自动出现 | 把完整命令交给你（已复制到剪贴板），粘贴进 Claude Code |
| **展开某个问题** | 同样——一次点击 | 同样——一次粘贴 |
| **加载结果** | 自动 | **同样自动** |

最后一行才是关键。服务器会盯着 `question-sets/`，所以**无论文件是怎么写出来的，图谱都会自己加载**——
不用挑文件，不用刷新。手动改一套问题，图谱会就地更新，并保留你当前打开的那个问题。生成第二套，它会切换过去。
展开某个问题，它会跟随新文件，因为它认得出这是同一个工作问题。

顶栏的状态灯会告诉你处于哪种模式：*live · can generate* 表示命令行工具在位；*live · watching* 表示
提问会给你一段提示词去粘贴。

想要一键生成：

```bash
npm i -g @anthropic-ai/claude-code
```

### 不用服务器也行

直接用浏览器打开 `viewer/index.html` 仍然可用，只是失去了自动监视。把 JSON 拖到页面任意位置，或用
`?data=../question-sets/你的文件.json` 传入。

## 仓库结构

| 路径 | 内容 |
|---|---|
| `skills/dont-stop-research/SKILL.md` | 技能本体。四个阶段：审题、生成、简报、输出 JSON，外加展开 |
| `skills/dont-stop-research/shared/` | 铁律、问题阶梯、卡片格式、两种输出格式 |
| `schema/question-set.schema.json` | 查看器依赖的 JSON 契约 |
| `viewer/` | 静态力导向图。d3 走 CDN，别无依赖 |
| `scripts/serve.py` | 陪伴服务器：监视 `question-sets/`，并在命令行工具可用时运行技能。只绑定 127.0.0.1 |
| `examples/us-china-tariffs/` | 完整范例的三个文件 |
| `scripts/validate.py` | 按 schema 和项目约束校验一套问题 |

## 七种问题类型

一套问题必须覆盖全部七种，并向**机制**和**张力**倾斜——研究最常死在这两处，无论研究者多资深。人们只收集
「是什么」，从不走到「为什么」；而一套内部没有真实分歧的问题，无论引了多少来源，产出的都只是综述而非立场。

| | 类型 | 它教的动作 |
|---|---|---|
| 1 | 含义 | 我们到底在问什么？哪些词在起作用？ |
| 2 | 全景 | 谁研究过这件事，他们发现了什么？ |
| 3 | **机制** | 为什么会这样？底下的故事是什么？ |
| 4 | **张力** | 谁不同意，他们最有力的理由是什么？ |
| 5 | 证据 | 人怎么可能知道这件事？什么算是证明？ |
| 6 | 边界 | 这个说法在哪里开始不成立？ |
| 7 | 意义 | 谁在意？如果答案反过来，什么会改变？ |

张力卡必须呈现**真实存在**的分歧，并且以其最强的形态呈现。如果某个题目本身没有活跃的专家分歧，技能被要求
直接说明这一点，而不是制造一场争论。

## 关于简报

每套问题都配一份为**完全不懂这个学科的人**写的导读简报——因为在任何一个具体问题上，大多数人都是如此，
包括邻近领域的专家。它是分层的：读完第一屏就能在十分钟内行动；想要推理过程就继续往下读。

它给你三个可以由完全不懂的人直接问出口的问题、真正理解与背书之间听起来有什么区别、会在答案里出现的词汇表，
以及最关键的一部分——如何核查我们的引注，并从我们自己没能确认的那一条开始。

在 solo 模式下，简报开头会有剧透警告，因为其中两节包含你最可能先想到的答案，提前读会破坏这项工作。

## 它不会做的事

不写文章。不给论点大纲。不出草稿。不告诉你该站哪一边。不通过总结材料来让阅读可以被跳过。

可被检验的标准：**如果你最后拿到的是自己没法当面辩护的东西，那就出了问题**——那三个复述问题就是你查明
真相的办法。

## 依赖它之前值得知道的局限

1. **各个部件证据充分，整体组合尚未验证。** 横向阅读、生成式追问、核心问题设计、以教促学，各自都有扎实
   证据；把它们组装成这个东西是一次有理据的赌注，而不是经过验证的干预方案。
2. **核实的可靠性取决于背后的搜索。** 技能能确认一个来源存在、且其摘要支持所附的说法。它读不了付费墙后的
   全文，也可能被一个真实、收录良好却错误的来源骗过。
3. **数字比引注更容易走失。** 在技术性题目上，更大的风险不是假引注，而是真数字脱离了它的适用范围——
   「损失 140 亿美元」指的是某一年上半年、且仅限货物贸易。简报里明确写了这一点。
4. **校准依据只是一段自述文字。** 比假定年龄好，但仍是猜测。一个谦虚描述自己的专家会拿到一套定得过低的
   问题。把 `context` 写得比你觉得必要的更详细。
5. **solo 模式下的剧透边界靠自觉。** JSON 不含预判答案，但正文和简报里有，没有任何机制阻止你提前翻看。
6. **它无法判断有没有人真的读了。** 它改变激励、让你试图解释时暴露空洞，但它不强制任何事。
7. **尚未制定敏感题目的内容政策。** 对于研究自己问题的成年人，这是合适的。如果你在 `guided` 模式下和
   年轻人一起使用，挑选题目并先审阅来源是你的责任——技能不会替你做。
